## Becoming A Merchant

1. Apply via "Become a Merchant" / "Apply Now" (`https://www.paydee.co/create-free-account`: name, mobile, email) or "Request a Demo" (`https://www.paydee.co/demo`).
2. Paydee assigns a 15-digit merchant ID (`merchantId` / `MPI_MERC_ID`, "assigned by acquirer bank").
3. Paydee enables payment methods for the merchant. Unenabled methods return `PAG01`. The message-type page says: "You might have additional approved payment methods... speak with our sales."
4. Get developer-portal credentials. Test and production endpoint URLs on `https://developer.paydee.co/` are locked behind sign-in ("Unlock Information").
5. Optional, one time: enroll a long-term RSA public key for key-exchange MAC verification using the enrollment file format `merchantId|Base64UrlPublicKey` (see `paydee-api.md`). If enrolled, every `/mkReq` must carry `mac`.
6. Agree the redirect and callback URLs with Paydee. No request field carries them in the public spec.

Required documents and KYC list: not documented in official docs (checked 2026-10-21). Ask Paydee sales.

## Credentials And Keys

There are no static API keys or shared secrets. Security is per-session RSA:

- Merchant ID (from Paydee).
- A fresh RSA-2048 key pair generated by your server for each payment session; public key sent in `/mkReq`.
- Paydee's per-session public key returned by `/mkReq`, used to verify response `MPI_MAC`.
- Optional long-term enrolled RSA key pair for key-exchange MAC.

Keep private keys server-side only. Do not log them. Store Paydee's session public key with the payment record so callbacks can be verified later.

## Environment Variables

Use names that match the target app's conventions. Suggested:

```text
PAYDEE_ENV=test
PAYDEE_ENDPOINT=https://devlink.paydee.co/mpi
PAYDEE_MERCHANT_ID=<MERCHANT_ID>
PAYDEE_ENROLLED_PRIVATE_KEY_PATH=/secure/path/paydee_enrolled_key.pem   # only if key-exchange MAC enrolled
PAYDEE_CALLBACK_URL=https://example.com/api/payments/paydee/callback     # as registered with Paydee
PAYDEE_RETURN_URL=https://example.com/payments/paydee/return            # as registered with Paydee
```

For production, set `PAYDEE_ENV=production`, the production endpoint from the portal, and the production merchant ID.

## Payment Methods

Per spec v5.0.0 and the developer site: cards (Visa, Mastercard, UnionPay; 3DS via GPayments), FPX online banking, e-wallets (Boost, Touch 'n Go eWallet, GrabPay, ShopeePay, Alipay, Maybank QR Push), DuitNow QR (`DNQR`, added v5.0.0), and Trade Credit (`TRD`, needs `MPI_EMAIL`). Use `GET /channels` to see what is live for your merchant ID.

## Settlement, Void And Refund Timing

- INITRECURR is settled at end of day (11 p.m.).
- Void cut-off is 11:30pm GMT+8 for cards and 11:59pm GMT+8 for most e-wallets and DuitNow QR; after that, refund.
- Refund credit to buyer: cards 2 business days, e-wallets and DuitNow QR 1 business day, Maybank QR Push 7 business days (manual).
- FPX refund function removed from the API in spec v3.0.3.
- Merchant settlement or payout schedule: not documented in official docs (checked 2026-10-21).

## Pricing

Paydee publishes no fee schedule; the site cites "competitive processing rates". Do not hardcode pricing. Point users to Paydee sales (`https://www.paydee.co/demo`) for current rates.
